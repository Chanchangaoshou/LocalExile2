## 问题 1（主阻断）：世界从不被 tick，0x2f7 进了队列却永不派发

**现象（已实证，Frida 多次会话）**：登录、选人、实例连接、区域生成全部正常；
客户端回 C→S `0x9a` 后，网关发出世界组 `0x2f7` CreateObject（玩家）；
客户端世界工厂 `0x142186c20` **确实创建了该消息对象**，但此后世界分发器
`0x1421343c0`、世界激活 `0x14212fd90`、队列排空、实体构造器 `0x141e705d0`
调用均为 **0 次**，类型登记从未以 `0xa7000ea0` 被查询。客户端停在加载界面，
无报错、无断线，直到用户退出。

**已实证的机理**：

- 一切世界派发都过总闸 `[world+0x84a]`；世界更新 `0x142130840`（虚表 +0x448）
入口无条件抬闸并派发 stamp=0 的消息——我们的 `0x2f7` 正是 stamp=0。由「派发
0 次」反推：**世界更新在实例会话期间从未运行**（菜单世界运行过 7 次）。
- **激活链已定（evening4）**：实例 `0x23` 的 handler `0x14212306d` 调世界聚合
对象（存于 `session+0x20f0`）**主虚表** `0x14339d1d0` 的 `+0x1f0`
= `0x1416820a0`，其首指令即调用激活 `0x14212fd90`。即 **`0x23` 是唯一已实证的
激活触发链**，与 `0x28` 无关（见下条 0x28 的最终定案）。

**`0x28` 的最终定案（evening5 审计，已实证，代码级证据链完整）**：

- **`0x28` 不是「实例身份」，是服务器的「带原因断开/踢出实例」消息。** 我们的
编码逐字节正确（与客户端 write 镜像 diff 为零）——失败是纯语义误用：客户端
忠实执行了一条合法的踢出。setter `0x14211f920` 与会话 leave 例程共用同一
拆除尾段；`[session+0x2270]` 状态机为 1=已关闭（ctor 初值）/2=连接已发起
/3=0x23 已提交。
- 我们填的「key」实为**断线原因码**：码 1/2 在客户端错误表里恰是账号名校验
类文案，故空名会话打印出账号规则全文；text 非空则原样回显（`Abnormal
disconnect: localtest`）。与「名字被校验」无关。
- 分发器兜底 `(0xf, "")` 是客户端在连接已死/EOF 时**自造默认断线原因**，
不是「真实服务器必发 0x28」的证据——evening3 的该推断作废。
- **结论：进图序列永不发 `0x28`（现状已如此，保持）。** fork 的
`InstanceProtocol.Identity()` 是误名，待改名 `DisconnectWithReason`
（已排队，随下一次网关部署一并做，避免实验窗口内无谓重启）。

**回归与对照（已实证）**：`0x28` 引入后（2026-11-04 16:11 起）连续三个会话
在区域包后约 35 ms 断线、无 `0x9a`；2026-11-04 17:01 的对照会话（停发
`0x28`，其余不变）`0x9a` 准时回来、`[SCENE] Set Source [河岸]` 正常、连接
保持——基线恢复，回归源锁定 `0x28` 本身。

**当前实验阶梯（单变量纪律，每级一个会话）**：

- **S1（已部署，待一次真机判读）**：网关提交 `c69313c`（exe 2026-11-04
17:12）。与 16:16 崩溃会话的**唯一差别**是 `0x23` 的 compact-int 值
0 → 1000：同时机（`0x1e` 之后、连接突发内）、同空队列、**不发 0x2f7**。
值 1000 的依据（evening4，已实证）：该值唯一已知消费者 `0x142130440`
在样本环为空时取 `值/1000.0` 作为动态分辨率标度候选并 min 进
`[world+0x66c]`，值 0 会把标度钳成 0。判据：
- 不崩 + Frida `world_activate`/`facet_callback` +1 → 值假说成立，进 S2；
- 不崩但激活未触发 → 查 `0x23` 的派发前置；
- 崩 → 看探针抓到的故障 VA 与聚合四字段（见探针条）。
- **S2（S1 成立后）**：`0x9a` 到达后先发 `0x2f7`（进队列、闸未开），
再发 `0x23`（值 1000）抬闸排空——期望激活→派发→实体构造一气呵成，
验收线是加载屏退出、人物站上河岸。若此级崩，嫌疑首次落到 1101 B
玩家 blob 的组件格式（此前从未被解析过）。
- **blob 离线审计（S2 之前可并行准备）**：钩类型登记 `0x141693840`
打印返回记录 `+0x28` 的组件表（个数/顺序/各 read fn），钩实体 ctor
`0x141e705d0` 的组件读环记录每组件线长，与 `PlayerObject.Blob()`
写入顺序逐项 diff。
- **激活之后若世界仍不 tick**：钩对象树遍历器 `0x141917d60` 与状态机
`0x142810b70`/`0x142812680`，判读实例世界是否根本不在对象树里
（缺的可能是「把世界挂进树」的某条实例消息副作用）。

**探针现状（v9，已部署在用户机，哈希 5020F249…）**：v4–v7 全部钩子
（工厂/派发/激活/排空/实体 ctor/类型登记/状态机/身份 setter 等），
外加 `Process.setExceptionHandler` 捕获故障 VA+回溯（交还客户端处理器），
以及在激活回调 `0x1416820a0` 入口 dump 聚合四字段：`[agg+0x98]` 区域
描述符、`[agg+0xfc8]`、`[agg+0x1270]`、`[agg+0x11c]`（0x23 值落点）。
若 fc8 非 0 而 area98 为 0，回调尾部是空指针解引用——比标度假说更直接
的崩因，一次会话可判。

**已被证伪/排除的方向（不要重复劳动）**：

- ❌ stamp 取值：ctor 初值就是 0，服务器填 0 正确。不要改 stamp。
- ❌ 实例 `0x21`/`0x22`：与激活无数据流关联，不要为了激活发它们。
- ❌ 「InstMgr tick 驱动世界更新」：探针实证整场未被调用，已作废。
- ❌ `0x28` 的任何形态（空名/账号名/改 key）：它是踢出消息，见定案。
- ❌ 类型哈希/加密/格式：`0x2f7` 逐字节正确解密、工厂已建对象、无抛错。

## 问题 2：选角界面职业永远显示第 0 行（野蛮人）

**现象（用户多次实测）**：任何角色在选角界面都显示野蛮人（Characters 表
第 0 行）且头像是 PoE1 风格。角色实际职业存的是 PoE2 编号（女巫=1，
DB 与网关日志可证）。

**从零审计结论（CLASS-DISPLAY-NOTES §6，已实证）**：

- **线格式无错位**：条目读函数 `0x142716700`、写镜像、拷贝构造三方互
证与 fork 的 `ListEntry15.Write` 逐字段 1:1 一致。
- **五个数值字段全部排除**：判别探针（`52de3f8`：U44=职业、U46=职业+5）
的字节经 2026-11-04 16:16 会话抓包程序化解码证实确实发出，用户同刻
实测界面仍是野蛮人——U40/U44/U46/Level/Class 无一是职业来源。先前
「U44 或 U46 二选一」的收窄作废；`5c87704` 的 U40 镜像同样作废。
- 排除项：S→C `0x16` 已全解（仅 u32+u16+u16，装不下职业）；联赛
StartStateSet=0 与官方 DefaultCharacters 集一致。
- 静态路线已穷尽：选角面板经 RTTI 只能定位到方法级，字段消费无法静态
隔离——改走活体指纹实验。

**当前实验（已部署，待用户下次登录一瞥）**：Auth 提交 `5fd6fd0`
（exe 2026-11-04 17:20，Core 424/424）。一次性角色 `bbbbbb` 携带
**§6.6 全字段互异指纹**：B4d=1, B51=2, U40=3, U44=4, U46=5, Level=6,
Class=7, B4c=8, B4e=9, B4f=10, B50=11；其余角色恢复普通构造（旧探针
已拆除）。判读：界面为 bbbbbb 显示的职业行号直接指认字段；若仍是
第 0 行 → 第二轮改动 `0x15` 报文级字段（Head32/Pairs/Tail/U74/U76/
Text30，现全 0/空）。得结论后拆除指纹代码。

## 问题 4：0x1e 里两块格式未逆出（升华/地形）

**现状（已实证）**：`0x1e` 的 LeagueStats 对表（flags0&0x80，元素构造
`0x1423bacb0`）与地形块（flags1&0x04，`0x14212aa70`）的 0.5.5 编码未
逆出；`AreaInstance.Encode` 遇非空 LeagueStats 或 TerrainData 直接抛
NotSupportedException（不发猜测格式）。新角色进普通区域两者皆空，
不受影响；**升华职业与 Delve 区域被此卡住**。

**后续思路**：采用「模式填充」法——可选段一次只开一个 flag、字段填
`00 01 02 03…`，钩 read `0x14211d340`，读完 dump 对象内存：消费字节
数 == 发送长度 → 格式对；递增模式出现的位置 → 线段到对象偏移映射。
人物进图（M2）之后做。
